# 0015. Страница игры на сайте — из `store/site/` игры; сайт забирает её сам раз в сутки через PR

**Решили.**

- Тексты и картинки страницы игры на gornitsa.games и её карточки на главной живут
  в репозитории игры: `store/site/page.ru.md` и `page.en.md` — поля в начале файла и текст
  страницы в Markdown. Картинки — ссылки на файлы `store/`, те же, что в карточке RuStore.
  Формат — [`../docs/08-publishing.md`](../docs/08-publishing.md#формат-storesite).
- Вид страницы — шаблон в репозитории сайта (`Nefeste/gornitsagames`), по брендбуку.
  HTML в `store/site/` не пишется, а сессии игр не правят страницы игр на сайте руками.
- PR игры, который меняет видимое игроку (версию для теста или магазина, возможности,
  снимки, цену, статус), в том же PR правит `store/site/`. Тест `store` игры проверяет формат,
  как проверяет карточку RuStore.
- Workflow сайта раз в сутки ночью и по кнопке читает `store/site/` с `main` каждой игры,
  собирает страницы, проверяет ссылки и картинки и открывает или обновляет один PR
  «Сайт: обновления игр»; из какого коммита игры взята страница — в `games.lock.json`
  сайта. Сливает владелец; сервер забирает `main` сайта сам, как и сейчас. Игра, чья папка
  не прошла проверку, в PR не попадает, а причина пишется в его описание.
- Закрытые репозитории (`nardy`, `votchina`) workflow читает токеном, которому разрешено
  только чтение содержимого этих двух репозиториев (секрет `GAMES_READ_TOKEN`
  в `gornitsagames`). Workflow с токеном запускается только по расписанию и по кнопке,
  не из PR; читает он только `store/`.
- В репозитории сайта по-прежнему правятся раздел политики конфиденциальности (он живёт
  только на сайте — [`../docs/07-privacy.md`](../docs/07-privacy.md)), страницы удаления,
  новости, главная и порядок игр на ней. Новая игра на сайте — строка в списке игр сайта;
  дальше её страница обновляется сама. Агент для сайта нужен только для такой
  редакторской работы.

**Откуда.** `store/site/` «Узоров» (готовые страницы и картинки для сайта) и «Анамнеза»
(текст страницы), `tools/store/site.ts` «Сказов» (картинки для сайта из материалов магазина).

**Почему.** Четыре игры меняются каждый день, а их страницы на сайте правились отдельными PR
из сессий игр: тексты и снимки отставали от игр (у «Нард» на сайте старая доска), PR сайта
из разных сессий мешали друг другу, а агенту игры приходилось знать вёрстку сайта. Когда
текст страницы лежит рядом с кодом, его правит тот же PR, что меняет игру, и проверяет тот
же тест, что карточку магазина. Сайт забирает изменения по расписанию, а не по событию из
игры: играм не нужны ключи к сайту, а обновление сайта не зависит от минут Actions закрытых
репозиториев, которые кончаются к концу месяца; workflow открытого репозитория сайта
минут не тратит. Для страницы игры сутки задержки не важны, а решает, что выйдет на сайт,
всё равно владелец, сливая PR.

**Платим.** Страница на сайте отстаёт от `main` игры до суток и до слияния. Формат
`store/site/` — договор между пятью репозиториями: меняется он только через устав, и сайт
в переходное время понимает старый и новый вид. Шаблон беднее ручной вёрстки: особые блоки
(турниры «Вотчины», проверка кубиков «Нард») — отдельные страницы сайта со своей вёрсткой.
В секретах открытого репозитория лежит токен чтения двух закрытых: только содержимое,
только чтение, срок — до 28.09.2027; продлевает его владелец.
