# 0018. Права по классам изменений; безопасные PR сливаются автоматически после ревью агента

Меняет правило «слияние в `main` — только владелец» из [`../docs/03-team.md`](../docs/03-team.md)
(решение владельца 03.10.2026).

**Решили.** Кто сливает PR, зависит от того, что он меняет.

| Класс изменения | Проверяет | Сливает |
|---|---|---|
| 1. Документы, спецификации, тесты, черновики контента (`review: draft`) | CI на PR и агент-ревьюер | автоматически |
| 2. Код, который не трогает деньги, сеть, данные игроков и выкладку | CI на PR и агент-ревьюер | автоматически |
| 3. Пути `deploy/`, `.github/`, `server/`, `src/money/`, политика конфиденциальности, `store/forms.md` и весь устав | CI на PR и агент-ревьюер | **только владелец** |
| 4. Выпуск в магазин, отправка наружу, траты, удаление данных | — | **только владелец**, как раньше |

- **Автослияние** (классы 1 и 2): workflow `automerge.yml` включает auto-merge GitHub, когда
  проверки CI на PR зелёные ([0019](0019-ci-on-pr.md)), на PR стоит метка `ревью: ок`
  и в PR нет путей владельца. Владелец видит такие слияния в утренней сводке и может откатить.
- **Пути владельца** (класс 3) записаны в `CODEOWNERS` каждого репозитория на `@Nefeste`;
  защита ветки `main` требует ревью владельца кода. Устав (`Nefeste/gornitsa`) — путь
  владельца целиком. Проект может добавить свои пути (например, папку с сетью или
  профилем), но не убрать перечисленные.
- **Ревьюер — всегда другая сессия, чем исполнитель.** Агент не ставит `ревью: ок` своему
  PR. Ревьюер проверяет PR по уставу, спецификации и тестам и либо ставит метку, либо пишет
  замечания. Если он сомневается, к какому классу относится PR (код задевает сеть, деньги
  или данные игроков вне путей владельца), метку не ставит и пишет «нужен владелец».
- В репозитории сайта слияние в `main` — это публикация на gornitsa.games
  ([0015](0015-site-from-store.md), [`../docs/10-channels.md`](../docs/10-channels.md)),
  поэтому PR сайта, меняющие видимое посетителю, — класс 4, их сливает владелец.
- Отметку `review: checked` по-прежнему ставит только человек; автослияние её не заменяет.
- Ни один агент не нажимает «Merge» сам: в классах 1 и 2 сливает GitHub по правилам выше,
  в классах 3 и 4 — владелец.

**Почему.** Владелец сливал каждый PR, и очередь на слияние стала главной задержкой
студии: документы, тесты и мелкие исправления ждали по нескольку дней, хотя их проверяют
CI и тесты. Решения, которые может принять только человек — деньги, право, выпуск,
данные игроков, то, что уходит наружу, — по-прежнему за владельцем, и GitHub проверяет это
по путям, а не по честному слову агента. Независимый ревьюер закрывает слабое место, которое
показал аудит 03.10.2026: один агент был и исполнителем, и проверяющим.

**Платим.**

- Ошибка, которую пропустили и CI, и ревьюер, попадает в `main` без человека. Защита —
  тесты, утренняя сводка и откат; выпуск в магазин всё равно делает владелец.
- Нужна настройка в каждом репозитории: защита `main`, `CODEOWNERS`, `automerge.yml`,
  CI на PR. Защиту веток и правило «ревью владельца кода» включает владелец; файлы под
  `.github/` — тоже путь владельца.
- Список путей не ловит всё: код сети вне `server/` формально попадает в класс 2. Это
  держится на ревьюере и на том, что проект добавляет такие папки в `CODEOWNERS`.
- Метку может поставить любой, у кого есть запись в репозиторий; правило «другая сессия»
  держится на дисциплине и проверяется в сводке.

**Когда пересмотреть.** Через две недели после включения — короткий разбор: сколько PR
слилось без владельца, сколько откатов. Сразу — если автослитый PR сломал выпущенную игру
или данные игроков.
