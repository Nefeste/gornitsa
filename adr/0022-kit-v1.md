# 0022. Что живёт в `gornitsa-kit`: загрузка в RuStore, автослияние, проверки подписи и APK

Продолжает пересмотр ADR [0002](0002-copy-not-share.md) от 03.10.2026: там решено, что общий
набор будет и начнётся с переиспользуемых workflow, а что и когда переходит в него —
отдельными ADR. Это первый такой ADR.

**Решили.**

- В набор [`Nefeste/gornitsa-kit`](https://github.com/Nefeste/gornitsa-kit) переходят пять
  частей CI, которые сейчас скопированы в каждую игру:
  - **загрузка APK в RuStore** — переиспользуемый workflow `rustore.yml` и действие
    `rustore-upload` (вместо `rustore.yml` и `tools/store/rustore.mjs` игр);
  - **автослияние по метке `ревью: ок`** ([0018](0018-change-classes-automerge.md)) —
    workflow `automerge.yml` и действие `automerge` (вместо `automerge.yml` и скрипта путей
    владельца игр). Правила — как в «Вотчине»: метка одобряет коммит, сливается только он,
    пути владельца из `CODEOWNERS` основной ветки, код PR не запускается;
  - **ключ подписи, проверка подписи и проверка содержимого APK** — действия
    `android-keystore`, `android-signature`, `android-contents` для шагов `android.yml`.
- **Остаётся в игре:** сама сборка APK (`android.yml`: prebuild, Gradle, переменные игры,
  выпуск), проверки только этой игры (бандл «Вотчины», номер приложения RuStore «Узоров»),
  проверки PR и весь код приложения — он по-прежнему копируется по ADR 0002.
- **Как вызывают:** по мажорному тегу, `@v1`. Внутри `v1` вход добавляется только со значением
  по умолчанию, при котором поведение прежнее; переименовать или убрать вход, сменить значение
  по умолчанию или выход — это `v2`, и игры переходят на него своими PR. Теги `vX.Y.Z` и
  передвигаемый `vX` ставит владелец.
- **Набор — путь владельца целиком** (`CODEOWNERS` — `*`): изменение набора меняет CI всех игр
  сразу, поэтому сливает его владелец, а не автослияние.
- **Перевод игры** — PR в игре по `docs/migration.md` набора, по одной игре; файлы `.github/` —
  пути владельца. После слияния копия в игре удаляется, а не правится: исправление теперь
  одно — в наборе.
- ПК-игры (ADR [0021](0021-pc-stack.md)) могут вызывать автослияние набора; шаги Android и
  RuStore им не нужны.
- Набор открытый (ADR [0017](0017-repo-visibility.md)): секреты приходят в него только входами
  и `secrets:` вызывающего workflow; ни адресов, ни данных закрытых репозиториев в нём нет.

**Почему.**

- Пять копий разошлись. Автослияние «Анамнеза» и «Узоров» снимает метку при новом коммите, но
  не закрепляет одобренный коммит — у «Вотчины» и «Сеней» это закрыто. Исправление в одной
  копии до остальных не доходило.
- Это код без логики игры: одинаковый у всех, меняется редко, а ошибка в нём — это
  незамеченный путь владельца при автослиянии или APK с чужой подписью в магазине. Такой код
  лучше держать в одном месте с тестами.
- Переиспользуемые workflow и действия GitHub не требуют пакета и сборки: игра пишет одну
  строку `uses:`.

**Платим.**

- Ошибка в наборе ломает CI всех игр сразу. Защита — тесты набора, его CI (тесты, actionlint,
  shellcheck), слияние только владельцем и откат: тег `v1` передвигается на прежний коммит.
- Игра зависит от открытого репозитория: если он недоступен, её CI с `@v1` не запустится.
- Игре с особым случаем приходится либо просить новый вход в наборе (с прежним поведением по
  умолчанию), либо держать свой шаг рядом с вызовом набора.
- Логика автослияния и проверок видна всем. Секретов в ней нет, но правила, по которым PR
  сливается сам, читаются снаружи.

**Когда пересмотреть.** Следующие кандидаты в набор — плагин и обёртка RuStore Pay, снимки
магазина, раздел политики — каждый своим ADR, когда он будет одинаков хотя бы в трёх играх.
Если игре понадобится разойтись с набором надолго — она закрепляет точную версию
(`@v1.0.0`), а владелец решает, нужна ли `v2`.
