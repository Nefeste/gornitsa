# 0019. CI на PR — быстрые проверки; APK и AAB — только на тег или выпуск

Заменяет часть ADR [0003](0003-expo-stack-ci.md) о том, когда запускается CI (решение
владельца 03.10.2026). Остальное в 0003 — стек, генерируемые нативные папки, сборка без
EAS с подписью постоянным ключом — действует.

**Решили.**

- **На каждый PR** в `main` — быстрые проверки: типы, линтер, тесты (те же команды, что
  в `AGENTS.md` проекта). Без prebuild, Gradle и сборки APK. Эти проверки обязательны для
  слияния (ADR [0018](0018-change-classes-automerge.md)).
- **APK и AAB собираются только на тег версии или выпуск** (GitHub Release). Ручного запуска
  сборки нет; слияние в `main` сборку тоже не запускает. Нужна сборка — ставится тег.
- Во всех workflow студии — **`runs-on: ubuntu-24.04`**, а не `ubuntu-latest`: с 19.10.2026
  `ubuntu-latest` переходит на Ubuntu 26, и сборки без нашего решения поменяли бы систему.
  Переход на новый образ — отдельным PR, после проверки сборки на нём.
- Обязательная проверка должна отвечать на каждом PR. Поэтому PR только с документами не
  исключаются из workflow через `paths-ignore` (тогда проверка повиснет «ожидающей»
  и PR не сольётся); если нужно сэкономить, шаги пропускаются внутри задачи.
- Проверки на PR экономят минуты: `concurrency` с отменой предыдущего запуска той же
  ветки, `timeout-minutes`, кэш зависимостей.
- Перед push агент по-прежнему сам прогоняет проверки (`04-process.md`): CI на PR — сетка,
  а не замена.

**Почему.** Минуты GitHub Actions — 2000 в месяц на все закрытые репозитории владельца,
платную оплату пока не подключаем (решение владельца 03.10.2026). Сборка APK — 15–30 минут,
а быстрые проверки — несколько минут (оценка, сверить по первым
запускам), поэтому проверять каждый PR дешевле, чем собирать каждое
слияние. Без проверок на PR не может работать автослияние: ему нужен зелёный CI до
слияния, а не после. Собирать APK нужно тогда, когда его кто-то поставит на телефон, —
к выпуску. `ubuntu-latest` меняется без нашего участия; закреплённый образ меняем сами,
когда готовы.

**Платим.**

- Минуты тратятся на каждый PR, включая документы; при активной работе пяти игр это
  заметная часть лимита. Остаток минут смотрит Дежурный.
- Ошибка сборки (Gradle, плагины, подпись) выясняется только на теге: тег может оказаться
  красным, и тогда — исправление и новый тег.
- Закреплённый образ однажды устареет, и переход на новый — наша работа.

**Когда пересмотреть.** Если минут стало не хватать к концу месяца — сокращать проверки
или подключать оплату (решение владельца). Когда GitHub объявит срок снятия образа
`ubuntu-24.04` — перейти на новый образ заранее.
